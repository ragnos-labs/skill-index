# Design Kit inside a CMS

The CMS Director resolves `design-kit` through the host's installed skill
index and reads the files the entry file's required-reads table names for a CMS
asset. It owns reference selection and any new discovery authorized by the
assignment. Reuse suitable admitted resources before fetching more. Inspect
actual pixels, assets, exports or code, distinguish discovery from use, and
reject unsuitable or unlicensed material. CMS brand values, learned corrections,
client scope and fixed copy remain binding; a general design-system export
cannot override them.

The Director passes the design pack defined in
[project-record.md](project-record.md), with its CMS additions and the
host-local resolved kit path.

Visual Maker resolves the same registered bundle on its own host and reads the
same required files before its first render. Verify the digest against the
pack; paths may differ across hosts, so record the mapping rather than
requiring an identical absolute path. The entry file's hold rule applies to a
missing or differing digest. Maker applies the chosen
direction and may fetch an exact admitted resource named in its pack; it
does not start a second reference search, import a collection, change the brand,
write campaign copy or select its own winner. Return editable source, renders,
actual resource use and observed defects.

Use the applicable CMS composition/discovery methods for real assets,
exact copy, output rounds, version lineage and object-specific permissions.
Kit guidance grants no additional account, rights, spend or write authority.
Only task-authorized saves occur; the Director owns any authorized post draft,
while Maker does not create posts or record outcomes on its own work. Human
approval, picks, final checks, scheduling and publication keep their existing
owners. A supplied offline fixture is evidence for a test, not a live CMS read.

A missing kit on another host is an honest capability gap. Use only separable,
authorized CMS fallback work and state that Design Kit was unavailable; do not
install it, bypass registry drift, invent its use or change permissions. On a
host where it is installed, merely naming it is insufficient: resolve and read
it, use the relevant methods, and preserve that evidence in the return.
